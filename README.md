# OTYS_HW1

## Описание задачи
В рамках данного задания необходимо было найти L1-норму матрицы двумя способами:
1. **Stride Access**.
2. **Sequential Access**.

> **Примечание по сборке:**
> Для переключения между методами в исходном коде необходимо:
> *   Для **Stride Access**: раскомментировать строки 5–19 и 51, закомментировать строки 21–35 и 53.
> *   Для **Sequential Access**: наоборот (закомментировать 5–19 и 51, раскомментировать 21–35 и 53).

## Методология тестирования
Анализ метрик проводился с использованием **Intel VTune Profiler 2026.4**:
*   **IPC** измерялся через *Performance Snapshot*.
*   **L1-промахи** измерялись через *Microarchitecture Exploration* (метрика `MEM_LOAD_RETIRED.L1_MISS`).

## Результаты бенчмарка

| :--- | :--- | :--- |

| **Sequential Access** | 2.005 | 0 |

## Анализ результатов

### Характеристики оборудования
Тестирование проводилось на процессоре **Intel Core i7-14700K**.
*   Объем L1 кэша: **48 КБ**.

### Интерпретация данных

**1. Sequential Access (Оптимальный вариант)**
*   Размер одной строки матрицы составляет 10,000 элементов `uint64_t`, что равно **80 КБ**. Это превышает размер L1 кэша (48 КБ). Однако благодаря механизму, процессор успевает подгружать следующие блоки данных из L2/L3 в L1 до того, как они понадобятся ядру. Доступ происходит линейно.
*   Процессор не простаивает. Пока выполняются арифметическое сложение, контроллер памяти уже подготовил следующие данные. Конвейер загружен полностью.

**2. Stride Access (Неоптимальный вариант)**
*   При обходе матрицы по столбцам шаг доступа равен размеру строки — **80 КБ**.
    *   Этот шаг слишком велик для эффективной работы стандартных L1 prefetchers, которые ориентированы на соседние линии кэша.
    *   Каждое новое обращение попадает в область памяти, которой сейчас нет в L1 (так как 80 КБ > 48 КБ, старые данные вытесняются или просто отсутствуют).
    *   Каждое обращение к элементу матрицы вызывает промах L1 и запрос к более медленным уровням памяти.
*   Процессор большую часть времени находится в состоянии ожидания, пока данные идут из памяти. Устройство простаивает, так как ему нечего считать.
